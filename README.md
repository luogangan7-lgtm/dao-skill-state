# 道 · Skill.state

Build, review and evolve reusable agent skills with measured, independently admitted changes.

- `dao-skill-state/` — the skill itself (install by linking this folder into your agent's skills directory).
- `skill-hub/` — thin entry skill that finds and loads hosted skills on demand (needs the binary below).
- `crates/skill-hub/` — Rust CLI: `index` / `check` / `search` / `get` over a local skill registry, plus `hook` for prompt-time skill pre-selection (optional Jev decision model).
- `crates/dao/` — DAO supply chain CLI. `dao intake` pins a source (git commit or local root), quarantines each skill (no execution; rejects escaping/dangling symlinks, devices/FIFOs, archives, oversize) and stores it content-addressed and read-only under `objects/<sha256>` with a content manifest and a per-source lock (commit, license evidence, symlink/hardlink/exec flags). Objects are read-only by design: `chmod -R u+w <store>` before deleting a store.
- `dao scan --store DIR (DIGEST...|--all)` — local deterministic rules over a staged object (re-hashes it first). Writes `scans/<digest>.json` with BLOCK / UNRESOLVED / REVIEW_REQUIRED / CLEAN, bound to `rules_sha256`. Best-effort: CLEAN is not proof of safety (held-out red-team: 5/20 hostile skills scored CLEAN).
- `dao check [SKILL_DIR]` — Rust port of `dao-skill-state/scripts/check_skill.py` (same JSON, messages and exit codes 0/1/2, PyYAML 1.1 semantics). Gate: `tests/fixtures/check_skill.json` (517 frozen Python results) in `cargo test`; live differential: `python3 -I crates/dao/tools/check_skill_diff.py --dao <bin> --checker dao-skill-state/scripts/check_skill.py --work <tmp> --generated --corpus <dir-of-skills>`.
- `dao normalize --store DIR (DIGEST...|--all)` / `dao relations --store DIR` — verbatim routing cards (`cards/<digest>.json`: name, description, use-when / not-for sentences, invocation lines, headings, language from the source path's locale or the script) and evidence-carrying relations (`relations.json`: same_content, same_entry, translation, drift, name_conflict, near_duplicate, family, references). Nothing is generated, merged or renamed.
- skill-hub dense recall (optional): `skill-hub index … --embed` writes `<registry>.emb` (bge-m3 via a local Ollama, loopback only). `search` and `hook` then fuse BM25 with dense recall by RRF ; the hook keep rule is unchanged (BM25 floor), dense recall only reorders the candidates; no sidecar, a mismatched sidecar, another model, or Ollama down/slow (`SKILL_HUB_EMBED_TIMEOUT_MS`, default 2000) → BM25 only.
- skill-hub reranker (optional): with `SKILL_HUB_RERANK=http://127.0.0.1:PORT`, the hook scores its candidates with a local reranker. The API is text-embeddings-inference `/rerank`, and `python3 -I crates/skill-hub/tools/rerank_server.py` serves `Qwen/Qwen3-Reranker-0.6B` (pinned) with a skill-routing instruction. The hook injects the single best candidate if it scores at least `SKILL_HUB_RERANK_TAU` (default 0.865, tuned for that model), and otherwise injects nothing. D7 round 3 (CI, 112 held-out cases): 98/112, against 88/112 for bge-reranker-v2-m3 (paired exact McNemar p=0.021), with all 36 chit-chat prompts answered by no skill. `--model BAAI/bge-reranker-v2-m3` still works; it needs `SKILL_HUB_RERANK_TAU=0.02`. The server uses the Apple GPU or CUDA when available; on CPU a request takes seconds, so raise `SKILL_HUB_RERANK_TIMEOUT_MS` (default 3000). The reranker runs before Jev, so while it answers, the prompt stays on the machine. If the server is down, slow or gives a bad answer, the hook falls back to Jev, which does send the prompt off the machine if `TYPESAFE_API_KEY` is set, or to the lexical rule. `SKILL_HUB_RERANK_TAU` must be between 0 and 1. Worst-case hook time is the sum of the stages: dense recall 2 s, reranker 3 s, Jev 4 s. On Apple Silicon with `mlx-lm` installed the server runs a 4-bit MLX build of the same model (D7 round 6: 97/112, ~1.3 s and 0.9 GB vs 98/112 for float16), and shifts each variant's scores so the default tau fits; without MLX the Apple GPU uses float16, because float32 there returned NaN scores for some requests (rounds 6–7: 88 and 92/112 vs 98 on CPU); the server now answers such a request 500 so the hook falls back instead of silently injecting nothing. One model thread serves requests in order, and a request that waited longer than `--max-wait-ms` (default 3000) is answered 503 at once so the hook falls back instead of queueing (merging requests into one pass, `--max-batch-rows`, made an M1 slower, so it is off by default). Many agents at once still exceed what one model serves within 3 s; by default the hook then injects nothing (`SKILL_HUB_RERANK_FALLBACK=lexical` restores the lexical rule, which in round 6 fired on 23 of 36 chit-chat prompts). On a GPU every pass also scores a fixed self-check row; if it drifts (the Apple GPU on GitHub's virtual Macs sometimes failed a pass silently), the request gets 500 and the hook falls back. Jev is opt-in only: nothing leaves the machine unless you set `TYPESAFE_API_KEY`.
- `dao upstream check --store DIR [--apply]` — compares each source path's newest lock with its source now (git: `ls-remote` of the requested ref; local: re-inspect the tree; pinned full-SHA requests have no upstream). `--apply` stages changed paths as new candidates through intake; existing objects, cards, receipts and champions are never modified.
- `dao eval gen --store DIR` / `dao eval run --store DIR --registry REG --searcher SKILL_HUB_BIN` — routing cases copied from cards and relations (should_trigger / should_choose / should_abstain; should_not informational), frozen by `set_sha256`; the run scores them with the hook's keep rule through skill-hub `search` and writes `evals/receipt-<set>.json` bound to the set, registry and searcher hashes.
- `dao admit --store DIR --digest D` / `dao promote --store DIR --digest D` / `dao rollback --store DIR --name N [--from D]` / `dao recover --store DIR` — admission is all-gates-pass: the object's manifest hashes to the digest and verifies; the scan receipt is from the current scanner and rules and is CLEAN, or REVIEW_REQUIRED with a named human approval in `approvals/<digest>.json`; the card is ok; relations.json and the eval set are current and name this digest; and the newest `dao-eval-receipt/2` for the set was produced under the hook's keep policy (top_k 3, the hook floor, rel 0.5), scored every gated case naming the candidate, evaluated this object's SKILL.md, and has no gated failure that expects or kept the candidate. `should_not` cases are informational by decision: their prompts share the skill's own vocabulary, so the model, not retrieval, applies the exclusion. Admission writes `admissions/<digest>.json` as a record; `promote` re-decides from disk and never trusts that file. Champion moves hold `journal.lock` and go through a journal (prepare → durable pointer write → commit, each entry recording promote or rollback); `recover` aborts or completes any interrupted move. Each `rollback` steps exactly one back from the current champion; `--from D` makes it a compare-and-swap, so a retry after a crash refuses instead of stepping twice. `DAO_FAULT=after_prepare|after_pointer` injects a crash for drills. Known limit: receipts (scan, eval, approval, admission) are unsigned — the store is trusted, and anyone who can write it can forge evidence.
- `dao publish --store DIR --target DIR [--apply] [--rollback]` — installs every champion as `<target>/<name>/` (dry run unless `--apply`). Each copy is checked against its manifest before it is swapped in, and `<target>/.dao-publication.json` records every version. Only directories that dao published are replaced or removed: an unmanaged same-named directory, or a hand-edited published one, is a conflict that refuses the whole apply (exit 1). `--rollback` re-publishes the previous version from the immutable store as a new version. Note that the next plain publish re-applies current champions, so to roll back for good, use `dao rollback` on the champion. `--rollback` always goes back one version from the latest, so repeating it toggles between the last two versions. Removing a champion does not unpublish it. `--apply` holds an exclusive lock on `<target>/.dao-publication.lock`, and manifests must hash to their digest before any byte is published.
- CI runs the skill's own format check and helper tests, plus fmt/clippy/tests for the Rust crate on Linux and macOS, on every pull request.
